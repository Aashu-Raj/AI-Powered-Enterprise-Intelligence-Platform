Project name: AI Popwered Intelligence Platform

1. Project Overview:
Build an AI chatbot that allows authenticated company employees to ask natural language questions about Github repo.

The purpose of the application is:
GitHub Repository
↓
Fetch Repository
↓
Index Repository
↓
Chunk Repository Files
↓
Generate Embeddings
↓
Store Chunks + Embeddings
↓
User asks a question
↓
Retrieve only relevant repository chunks
↓
Send relevant context to LLM
↓
Generate grounded answer

The chatbot should answer questions based on the actual contents of the selected github repo rather than relying only on the LLM's general knowledge.
Examples of questions users should be able to ask:
1. How does authentication work in this repo?
2. where is the database connection created?
3. Where is this function called?

The first version should focus on repo ingestion, indexing, semantic retrieval, and question answering.

2. Current V1 Scope
The initial version consists of exactly these satges:
1. Parse GitHub repository URL
2. Resolve repository reference and commit SHA
3. Retrieve repository tree
4. Filter files
5. Fetch file contents
6. Chunk files
7. Generate embeddings
8. Store repository chunks and embeddings
9. Retrieve relevant chunks and answer questions using an LLM

Do not implement the following in V1:
1. GitHub webhooks
2. Automatic incremental re-indexing
3. Advanced symbol/reference search
4. AST-based code intelligence
5. Language server integration
6. Code execution
7. Pull request analysis
8. Commit analysis
9. Git history analysis
10. Autonomous code modification
11. Autonomous coding-agent tools
12. Submodule recursive indexing
13. Complex multi-agent architecture
14. Fine-tuning
15. Repository-wide summarization pipelines

These may be added later.

3. Core architectural principle
The most important design principle is:
The GitHub repository is the source of truth, while the local database contains an indexed snapshot of a specific repository version.
Every indexed chunk MUST be associated with the exact Git commit SHA from which it was generated.
Never treat a branch name such as main as the permanent identity of indexed repository data.
For example:

Repository:
    owner = tiangolo
    repo = fastapi

User selected:
    ref = main

At indexing time:
    main → abc123456...

Indexed snapshot:
    commit_sha = abc123456...

Every chunk:
    repository_id = ...
    commit_sha = abc123456...

If main later changes to another commit, the old chunks still clearly belong to the old commit.
This requirement must be preserved throughout the entire codebase.

Use postgresql as the primary database.

4. Authentication
The application must support employee authentication. Passwords must never be stored as plaintext.

## Final instruction to Cursor

Implement this project incrementally.

Do not implement the entire system in one step.

Start by creating the project structure, configuration, PostgreSQL connection, SQLAlchemy models, and Alembic setup.

Then implement authentication.

After the authentication foundation is working, implement the GitHub repository ingestion pipeline.

At every stage, write tests and keep the application runnable.

Do not silently change the architecture or introduce unnecessary infrastructure.

Prefer simple, maintainable, testable Python code over premature optimization.
